# 変更の進め方の決定

> For the English version, see [../../en/decisions/development-flow.md](../../en/decisions/development-flow.md).

並行する PR・長いブランチ・レビュー・公開と文書の進め方について閉じた判断と、その経緯。日々の規則は
`CLAUDE.md` の "Development" にある。

## 並行する PR は、マージの順に依らない形にする

- **決定** (2026-10-04): ある PR のテストが、並行して開いている別の PR の挙動の変更とぶつかったら、
  まず、どちらが先にマージされても成り立つ形を探す。2 つを合わせた木で、全体が通ることと、変異に
  耐えることを示してから push する。
- **理由**: ぶつかりをマージの順に任せた PR (「後からマージする側が書き換える」) は、相手がマージ
  されると落ちるとして、レビューで差し戻された。順を決めるより、順を決めずに済む形が選ばれた。
- **やり方**:
  - 2 つの PR が両方持つ修正は、片方に寄せる。
    [#43](https://github.com/semnil/urx-lcd-sim/pull/43) は、
    [#35](https://github.com/semnil/urx-lcd-sim/pull/35) が全部の経路で直す欠陥の 1 つの経路だけを
    直していたので、#43 からその修正を外した。main を取り込むときに同じ修正が両側で見つかったら、
    判定を 1 つの関数に寄せて、もう片方はそれを当てるだけにする。テストは片側にまとめ、もう片側だけが
    確かめていた点を 1 行足す。
  - 別の PR が変える挙動を固定したテストは、前でも後でも成り立つ関係に書き直す。刻みの大きさの
    代わりに、「Shift を押したドラッグは、素のドラッグの 5 分の 1」「Shift を押したホイールは、Shift を
    押した矢印キーと同じだけ回す」と書く。
  - 外した値を、相手の PR のテストが持っているかは、合わせた木に変異を当てて確かめる。その日、
    ホイールの Shift の刻みはどちらも持っておらず、変異が生き残ったので、関係のテストを足した。
  - 合わせる試しは、そのための detached worktree で、相手のブランチを 1 本ずつ合わせて行う。両側が
    テストを足しただけの衝突は両方を残し、走らせる前に、両側のテストの名前を数える。
- **実害の記録** (2026-10-04): #43 のレビューが、
  [#37](https://github.com/semnil/urx-lcd-sim/pull/37) がマージされるとテストが落ちること、#35 が直す
  ものの一部を直していることを指摘した。同じ日、#35 のレビューは、
  [#40](https://github.com/semnil/urx-lcd-sim/pull/40) が足す遮断を #35 にも入れるよう求めた。
  レビューは改められ、その指摘は取り下げられた。#40 を先にマージし、#35 をその上に載せ直して、キーの
  操作の回帰テストで、2 つの制限が一緒に成り立つことを示した。同じレビューが見つけた、#35 より前から
  ある欠陥 (満杯のカードへの保存) は #35 から外し、
  [#46](https://github.com/semnil/urx-lcd-sim/pull/46) で直した。

## 長いブランチを main へ載せ直す

- **決定**: 進んだ main へブランチを載せ直すときは、衝突する所だけでなく、衝突しない所も合わせる。
  PR に書いたことは、新しい木で測り直す。
- **衝突が無くても合わせる所**:
  - main が足した部品が、ブランチの書いた規則から外れる。main の変更で、ブランチのテストの前提が
    無くなる。ブランチの docs の主張が、main では成り立たなくなる。main の取り込みをコミットする前に、
    取り込む PR が確かめた事項を、ブランチの docs の「未確認」「〜でのみ確認」の記述と照らす。
  - CSS は詳細度でぶつかる。衝突なく入ったブランチの規則 `.lcd.is-udk:not(.has-readout) .main` は、
    `:not()` の分だけ、ガラスを覆うシートの main の規則より強く、main のテストが落ちた。同じ詳細度の
    規則を、もう一方の後ろに置く形にした。
  - main が仕組みを変えていたら、ブランチの新しい経路をその仕組みに載せる。main が、ブランチの
    触ったモジュールを作り直していたら、ハンクを合わせず、main の仕組みの上にブランチの挙動を
    書き直す。コミットメッセージも、新しい差分に合わせて書き直す。
  - main に同じ修正が既に入っていたら、ブランチのその差分は rebase で消える。コミットを docs と
    テストだけのものに改め、題も付け直す。
- **確かめ方**:
  - 衝突の無いファイルが、どれも `git merge-tree --write-tree origin/main <旧い先端>` の木と一致する。
  - `src/` に触れるコミットを、1 つずつ `git archive` で取り出して、`tsc --noEmit` と全体のテストに
    掛ける。直しは、挙動を変えたコミットへ畳み、畳んだ後にもう一度型を検査する。
  - モジュールを main の仕組みの上に書き直した後は、両側が足した行のうち無くなったものを、
    ファイルごとに行の集まりとして数える。無くなってよいのは、書き直した所だけ。書き直した分岐には
    変異を当てる。
  - PR の図は、撮ったときのスクリプトで撮り直して、前のものと画素で比べる。本文で測った値は、
    新しい木で測り直すか、旧い先端のハッシュを添えて残す。
  - push は `--force-with-lease=<ブランチ>:<元のハッシュ>` で行う。
- **実害の記録** (2026-10-04 と 05): 1 日に 3 本のブランチを main へ載せ直した (23・47・44 コミット)。
  4 本目は、兄弟の PR のマージを追って 5 回載せ直した。そのうち 1 本は、直した行を型の検査に掛けずに
  push して、CI で落ちた。main の仕組みの上に書き直したモジュールに変異を当てると、欠陥が 1 つ出た
  (待っている間の変更を書き落とす保存)。

## レビューが、兄弟の PR で直った欠陥を指したとき

- **決定**: レビューが指した欠陥を、その後マージされた兄弟の PR が直していたら、ブランチを、その
  修正を持つ main へ載せ直して、そこで測る。
- **実害の記録** (2026-10-04): [#45](https://github.com/semnil/urx-lcd-sim/pull/45) の 2 回目の
  レビューが、「別の指が、ドラッグ中の指の値を変える」と指摘した。レビューが読んでいたのは、#45 を
  最初に切った base のコードで、その時点でマージ済みの #37 が直していた。旧い base では起きること
  (2 本目の指で、両方の値が 4.00 dB になる) と、main では起きないこと (片方だけが 3.20 dB になる) を
  示し、2 つの値を同時にドラッグするテストを足して固定した。

## 保存した値の意味を変えるとき

- **決定**: 保存される画面の状態の意味を変えたら、前の版が保存した値から始めて確かめる
  (`CLAUDE.md` の "Checking a change on the screen")。
- **実害の記録** (2026-09-27、[#22](https://github.com/semnil/urx-lcd-sim/pull/22) のレビュー):
  前の版で、Edit を開いたまま一覧を Simple へ切り替えて保存された値 (`scene.bank=Simple`・
  `ui.sceneMenu=Edit`) から新しい版を開き、Standard へ切り替えると、Edit が戻った。

## 変更の記録のファイルを持たない

- 2026-10-16 に決めた。消したものと、代わりになるものは、
  [#95](https://github.com/semnil/urx-lcd-sim/pull/95) にある。

## push ごとに Pages を公開し、タグと Release を作らない

- 2026-10-25 に決めた。残る流れと、APP Version がビルドしたコミットを出すことは、
  [#133](https://github.com/semnil/urx-lcd-sim/pull/133) にある。
- **経緯**: v0.3.0 から v1.0.0 までは、`package.json` の `version` だけを変える PR のマージで、タグと
  下書きの Release を作り、その push から Pages を公開していた。`version` は、もう動かさない。

## 英語を基本の言語にする

- 2026-10-20 に決めた。訳したものと、付けたリンクは、
  [#112](https://github.com/semnil/urx-lcd-sim/pull/112) にある。
- **経緯**: マージ済みの PR の本文は、そのままにした。本文にある日本語は、引用 (検索の語、日本語の
  文書の見出し、画面の文字、フォームの選択肢の名前) と、その PR を書いた時点の見出し 1 つ。
