# ガイドの図についての決定

> For the English version, see [../../en/decisions/guide-figures.md](../../en/decisions/guide-figures.md).

ユーザーガイドの画面キャプチャが何を決め、何を決めないかについて閉じた判断と、その経緯。規則の本文は
`CLAUDE.md` の "Primary source" にある。図からの値の取り方は
[design-tokens.md](../design-tokens.md) の「採取方法」が正。図の番号は `reference/ug-lcd/` の抽出名。

## 図だけでは決まらないもの

- **決定**: 形・寸法・色は図から測ってよい。何が並ぶか・いくつあるか・大文字と小文字は、図だけでは
  決めず、実機で確かめる。
- **理由**: 図は、撮ったときのファームウェア・機種・状態のもので、それがどれだったかは図から読めない。
  配色や 480x272 という寸法のように、図の中で完結して測れるものは図から取れる。何が並ぶか・いくつ
  あるかは、図の外の状態で変わるので、図を根拠にすると気付かないまま間違える。
- **実害の記録** (チャンネルバンク): 図によってバンクのセルの数が違う (INPUT の側が 3 個と 4 個、
  OUTPUT の側が 1 個と 3 個)。CH13/14 と CH15/16 が写る図もあるが、実機の入力は 12 まで。実機の
  HOME では、INPUT の側が 3 バンク (CH 1 - 4、CH 5 - 12、FX 1 - 2)、OUTPUT の側が 1 バンク (MIX、ST、
  STREAMING) で、図に写る PAD のストリップは 3 つ目のバンクに出ない。結果は `src/model/units.ts` と
  [screen-inventory.md](../screen-inventory.md) の「チャンネルバンクの構成」にある。
- **実害の記録** (確かめていない機種): URX44V で確かめたバンクの名前の規則 (3 つのグループから 2 行)
  を、URX22 にそのまま当てていた。`CH 7 - 10, FX 1 - 2` が 1 行で、ほかより広いボタンになった。
  [#93](https://github.com/semnil/urx-lcd-sim/pull/93) で、2 行・同じ幅にした (2026-10-16)。
- **実害の記録** (薄く写った要素): p074-1 の SCENE LIST の箱では、選んでいる `02` だけが (80,80,88) と
  薄く、題は白い。図に薄く写った要素は、明滅の途中のことがある。実機では、番号だけが明滅し、題は
  いつも出ていて、▶ の行を選んでいる間は何も明滅しない。明滅と点灯は、部品と状態を 1 つずつ分けて
  聞く。

## 根拠に使わない図

- **決定**: p036-1 は、HOME の [Sends] の根拠に使わない。この図はボタンを消灯で描く。実機は、送り先の
  色で点灯する (p047-1 と p157-1 のとおり)。
- **決定** (2026-09-18): p114-1 のタイトル札は、札の位置と幅の根拠に使わない (画面全体の雰囲気と
  角の形は参考にしてよい)。実機は、札と右側の部品の間に、EQ の画面と同じ間隔を持つ。図の側で
  見分けられる: ツールバーの右側の部品は、どの図でも x384 から始まる。札の右端は、札の幅が 126 の図
  (p113-1・p114-1・p115-1) では x379 で間隔 4px、幅が 116 の図 (p103-1・p099-1・p106-1) では x369 で
  間隔 14px。実機は 14px の側。
- **決定** (2026-09-18): p056-1 の `Brightness` と p061-1 の `Peripheral` は、大文字と小文字で
  書かれているが、題の根拠に使わない。実機は、この 2 つの題を大文字だけで出す (同じ章の p055-1 は
  `LANGUAGE`)。p042-1 の Operation Mode は、実機でも大文字と小文字で、題も SETUP の箱の見出しも図の
  ままにする。BRIGHTNESS は、値を入れる所が 1 つなので、開いた直後から Screen の値にマゼンタの枠が
  付く (p056-1 のとおり)。
- **実害の記録**: [Sends] の点灯と消灯を図で数えたとき、消灯に数えた図のうち 3 枚は、このボタンが
  紙面に出ていない図だった。図を数える前に、紙面で見える範囲を当てる。

## 紙面に出ていない画素

- **決定**: 紙面に出ている範囲の外の画素は、根拠に使わない。範囲は `reference/ug-lcd/visible.json` に
  あり、規則は `CLAUDE.md` の "Primary source" にある。紙面で隠れた部分は、見えている部分を別の図に
  重ねて復元する。
- **理由**: ガイドが画面キャプチャを置く 117 か所のうち、29 か所は、クリップで画像の一部 (3〜22%)
  だけを見せている。抽出は、クリップの前の画像の全体を取るので、残りの部分には紙面に出ない内容が
  入る。p038-4 のツールバーには、実機に無い四角のアイコンが 4 つあり、p048-5 には、見えない位置に
  STREAMING のストリップがある。画像の一部に別の画像を重ねて直したキャプチャは無い (PDF の中の画像の
  描画 235 件を、画像の一覧と突き合わせた)。
- **実害の記録** (2026-09-14 と 15): 紙面で隠れた部分を根拠にした比較が差し戻された。翌日にも、
  隠れた画素を根拠に数えたことが 2 回あった。CH SETTING の Color と Icon の印に p093-1 の上半分、
  HOME の [Sends] の消灯の色に p048-5 と p049-1、選択中のストリップの枠に p048-5。

## 状態で変わる色

- **決定**: 点灯や選択のように状態で変わる色は、その状態が写っている図からだけ取る。色を取る前に、
  その部品が点灯して写る図があるかを探す。
- **決定** (2026-09-20): HOME のストリップの印は、それぞれのボタンと同じ色にする。INS FX・HI-Z・
  HPF がシアン、Φ がオレンジ、+48V が赤。
- **実害の記録**: INS FX の印を、p090-1 の淡い灰 (`#d6ced6`) で描いていた。この図には消灯の印しか
  写っておらず、淡い灰は消灯の側の色だった可能性がある。
- **実害の記録** (2026-09-21): docs は、+48V の点灯の色を「写した画像は無い」として、パレットの別の
  赤を当てていた。p047-1 の CH 4 に、点灯の印が写っていた (核の色は (206,69,41)、`#ce4529`)。
  見つけたのは、その色と完全に同じ画素をどの図でも数える走査で、目で探したときには見落としていた。
  色は [design-tokens.md](../design-tokens.md) にある。

## アイコンは画素の差だけで選ばない

- **決定**: アイコンの形は、画素の差に加えて、形として読める特徴 (歯の数、切れ込みの深さなど) でも
  比べる (`CLAUDE.md` の "Primary source")。
- **実害の記録**: SETUP の歯車を 8 歯で描いていた。実機は 6 歯 (`src/ui/icons.ts`)。2026-09-13 に、
  MONITOR の [Setting] タブで同じ誤りを繰り返した。画素の差 (XOR) だけで当てはめると、谷の浅い
  8 歯の歯車が最も良い点になる。

## ガイドの本文が決めること

- **決定**: 図で決まらない点は、挙げる前に、ガイドの本文で引く (`CLAUDE.md` の "Primary source")。
- **実害の記録** (2026-09-20): microSD のカードについて、挙げようとしていた 4 点が、本文で決まった。
  仕様の表の microSD Card Slot が WAV 24-bit であること (録音の大きさの計算に使う)、File list が
  「選んでいるフォルダーとその 1 階層下」を出すこと、[↑] が 1 階層上へ移ること、Folder name display が
  収まらないパスの末尾の側を見せること。
- **経緯**: 本文も、実機と違う所がある。見つかったものは、[known-issues.md](../known-issues.md) の
  「実機にも無いもの」と、[screen-inventory.md](../screen-inventory.md) のその画面の節にある。

## 同じ部品の図どうしが食い違うとき

- **決定**: 同じ部品の 2 つの図が食い違うときは、両方の図との画素の差を出して、操作者が選ぶ。
- **実害の記録** (2026-10-12、[#72](https://github.com/semnil/urx-lcd-sim/pull/72)): ピッカーの
  シートの名前の 2 行の間隔は、wide/p059-1 が 14px、p100-2 が 16px で、画素の差で良い方はシートごとに
  逆だった。修正の前後の拡大と差の表を並べて示し、どのシートも 14px と決まった (p100-1 の箱は 16px の
  まま)。結果は [screen-inventory.md](../screen-inventory.md) の「画面に重なるシート」にある。

## 実機に答えのある問いは、実機で答えを出す

- **決定** (2026-10-02): 実機の挙動が確かめられていない点の答えは、「実機を観測して合わせる」に
  する。「実機に合わせる」と「実機を見ずに決める選択肢」を並べた問いは出さず、確かめる側へ回す。
  問うのは、実機に答えの無い点だけにする。保存の形、ダイアログの最初のフォーカス、docs とコードの
  どちらを正とするか、など。
- **経緯**: 品質の監査が判断に回した点を、答えに「実機に合わせる」を入れて 4 問ずつ聞いた。その答えが
  15 回続けて選ばれ、その後の点にも同じ答えが指定された。2026-10-03 には、変更の後に出した「DELAY の
  丸めを残すか外すか」の問いに、実機を測ったかを問い返された。

## LCD から読んだ値は、写さずに当てはめる

- **決定** (2026-09-26): 実機の LCD から読んだ長さは、読んだままでは使わない。すべての読みに合う
  1 つの目盛りを探し、テストに読みと許容差 (0.9 mm) を持たせる (`src/model/dynamics.test.ts`)。
- **理由**: 画面から読んだ値は誤差が大きい。作るのは、計算で出せる値にする。
- **決定**: 式を決める前に、すべての記録を式に入れて照らす。両端の記録と、中間に当たる記録も入れる。
  シミュレーター自身の丸め方を前提にしない。区別できない候補 (計算の順、`Math.round` か `toFixed` か)
  が残るときは、それを分ける読みを 1 つ足す。
- **実害の記録** (2026-10-03): DELAY の 4 つの欄の元になる音速を、343.6 → 343.589 → 343.59 と 2 回
  訂正した。1 回目は、両端の段を入れずに範囲を出した。2 回目は、シミュレーター自身の「中間を上へ寄せる
  補正」を前提に当てはめた。
- **経緯**: 目盛りを変えると、図の点灯した行に合わせて決めた既定値 (RECORDER の OUT の -15.6 と
  -13.5 dB、p081-1 の 54 行と 60 行) がずれるので、行の数から出し直す。また、画面の描き方は、音の
  応答と同じとは限らない。SSMCS の MID のベルは、p112-1 に合わせた Q × 0.696 で描く
  (`SSMCS_BELL_Q_SCALE`)。4 バンドの EQ のベルは、Q を半分にした形が p106-1 に最もよく合った。

## ガイドの本文の小さなボタンの絵

- **決定**: ガイドの本文の中の小さなボタンの絵も、LCD の画素として使う。キャプチャに無い状態の
  見た目は、この絵の中から探す。絵は 52x31 と 42x31 の埋め込み画像で、色はキャプチャと同じ値
  (面が (74,81,90)、緑の三角が (49,235,115))。`pdfimages -f <page> -l <page> -png` で取り出す。
  ページは、図の番号の 3 桁。
- **気を付ける理由**: 同じ画像が、複数のページで使い回される (Play タブの説明の再生ボタンは、Record
  タブの説明の再生ボタンと同じ画像)。絵は、その説明の画面で撮ったものとは限らない。使うときは、
  そのことを添える。
- **経緯** (2026-09-14): RECORDER の [Play/Pause] が、止まっているときに持つ印を、この絵から
  決めた。
