# Layout and type decisions

> For the English version, see [../../en/decisions/layout-and-type.md](../../en/decisions/layout-and-type.md).

部品の配置と、字の大きさ・位置について閉じた判断と、その経緯。規則の本文は `AGENTS.md` の
"Checking a change on the screen" にある。画面ごとの今の姿は
[screen-inventory.md](../screen-inventory.md) と [design-tokens.md](../design-tokens.md) が正。

## A part that comes, goes or changes moves no other part

- **決定**: 画面は実機と同じ配置にする。部品を出す・隠す・空にする、値が変わる、のどれでも、
  ほかの部品の位置と大きさは変えない。画面ごとの結論は
  [screen-inventory.md](../screen-inventory.md) の「INPUT 画面」「入切ボタンの名前」
  「STEREO/CUE メーター」「HOME ストリップの構成」にある。
- **理由**: 実機の画面は配置が固定されている。flex の項目は、指定しなければ縮み
  (`flex-shrink: 1`)、中身の幅より狭くはならない (`min-width: auto`)。空の要素は場所を取らない。
  既定のままの配置は、周りの部品を動かす。DOM のテストは要素の有無と順序しか見ないので通る。
- **実害の記録** (2026-09-06〜07、1 つのセッションで同じ形の直しが 5 回):
  - INPUT 画面で、ヘッドアンプを持たないストリップのパネルを丸ごと消していた。パネルはどの画面にも
    残し、中身だけを空にする。
  - 同じ画面で、残したレベルバーを左上に詰めていた。Gain を持つ画面と同じ位置に置く。
  - 入切ボタンの名前を、点灯のときだけ太くしていた。太い字は幅が広い。太さは入でも切でも同じにする。
  - HOME で CUE を点灯すると、メーターの名前と枠がレールの列に加わり、[Sends] とノブモードの
    ボタンまで縮んだ。
  - HOME のレベルの値の箱が、`-4.00` の符号の分だけ広がり、ロータリーを押しのけた。
- **実害の記録** (2026-09-20、逆向きの形): OSCILLATOR の `.osc-params` は、空の `div` を置いて
  1 列目を空けるつもりの flex で、空の `div` は幅 0 だった。Sine Wave の Frequency は、行の左端が
  2 列目にあったので正しく見えた。Burst Noise では、Width が 2 列目、Interval が 2 列目と 3 列目の
  境に立っていた。今は、画面の下端のノブの区画の上にセルを置く。DOM のテストは子の並びだけを見て
  通っていた。
- **実害の記録** (2026-09-22、2 回):
  - RECORDER の Play タブで、止まっている間は経過時間と周波数を空にしたら、中身の無い行の高さが 0 に
    なり、進捗バーが上がった。行は高さを保ち (`min-height: 1lh`)、3 つの状態の矩形が一致する。
  - カードの画面の空き容量を、1 行だけ縦の中央に置いていて、図より 7px 高かった。p088-1 の 1 行は、
    名前の行が空の 2 行組の 2 行目の位置 (y73..81) にあり、名前の入った p089-1・p092-1 と同じ高さ
    だった。図ごとに行の数が違うときは、少ない方の行が、ほかの図のどの行の位置にあるかを先に測る。

## The browser's own scroll bars

- **決定**: スクロールする箱は、ブラウザ自身のスクロールバーを隠す。隠す規則から漏れた箱があると、
  `src/style/columns.test.ts` の "the browser's own scroll bars" が落ちる。新しい箱の確かめ方は
  `AGENTS.md` の "Checking a change on the screen" にある。
- **実害の記録** (2026-09-13): TIME ZONE のダイアログを、スクロールバーを隠した撮影で確かめて、
  完了と報告した。スクロールバーを出すブラウザでは、描いたバーの内側にブラウザ自身のバーがあって
  二重になり、横にもスクロールした。SAVE/LOAD のファイルの一覧にも同じ欠陥があった。

## A text size is chosen by the pixel difference from the figure

- **決定** (2026-09-14): 字の大きさは、候補を描いて、図との画素の差が最も小さいものを選ぶ。位置は
  大きさと分けて、インクの行と列のずれを測って決める。手順は `AGENTS.md` の
  "Checking a change on the screen" にある。
- **理由**: 書体が実機と違うので、高さが合う大きさでも、幅と位置は合わない。字の行がずれたまま、
  画面全体の差で大きさを選ぶと、インクの少ない小さい字ほど差が小さく出る。位置の誤りを、大きさが
  吸収してしまう。
- **実害の記録** (2026-09-14): コントロールごとの字の大きさを、ガイドのインクの高さに合わせて入れたら、
  図との平均の差が 7.75 から 8.03 に増えた (HOME のリンクの状態で +4.9。14px のバッジが枠を詰め、
  ストリップが 3px ずれた)。画素の差で選び直し、位置を別に合わせて 7.48 になった。
- **実害の記録** (2026-09-15): 窓をずらすことを許す採点で選んだ値のうち 3 つが、撮ってみると悪く
  なった。SAVE/LOAD と RECORDER の一覧の見出しの 12px・太字 (見出しの領域の差が +17〜48%)、HOME の
  リンクのハートを 1px 下げる (+54%)、サイドレールのタブ名の太さ 600 (8 画面で減ったが、OSCILLATOR で
  +6.8%、SEND TO で +13.3%)。
- **経緯**: 字以外の形も同じ選び方でよい。2026-09-20、シートの角の丸みを 5・6・7・8px から選んだ。
  採点は部位ごとの窓 (右上・右下・左下・右辺・下辺) で取った。合計だけを見ると、下の 2 つの角が
  良くなった裏で右上が悪くなっていたのを見落とす。差が最も小さい候補が上と下で違ったので、
  `border-radius` を上と下で分けた。

## Text on one row is matched by its ink rows

- **決定**: 1 行に並ぶ字の組は、面積の差ではなく、インクの上端と下端の行を図と並べて決める。
- **実害の記録** (2026-09-27): SCENE LIST の番号は、差で選んだ 11px・1px 上で、題と縦の位置がずれて
  見えた。p076-1 と p077-1 では、番号と題が同じ大きさで下端がそろっている (p077-1 の `02` と
  `01234-56789` はどちらも y162..170)。描画は番号が 2 行上だった。
  [#21](https://github.com/semnil/urx-lcd-sim/pull/21) で 13px・ずらし無しにした。
- **実害の記録** (同じ修正): `translate` は見た目だけを動かして幅を増やさないので、題を左へ寄せても、
  箱の中の題は `…` で切れた (箱の `gap` を詰めた)。詳細度の高い規則の `translate: 2px 0px` は、基底の
  規則 `.scene-title { translate: 0 1px }` の縦の 1px も打ち消していたので、規則ごと消すと題が 1px
  下がった。ずらしの規則を消すときは、基底の規則の値が戻ってこないかを撮って確かめる。

## A box is read with the band under its face

- **決定**: 箱の寸法を図から取るときは、面の色の外接矩形ではなく、1 列を上から下まで画素で読む。
- **理由**: 面の下に 3px の帯を敷く部品 (タイトル札・プルダウン) は、面の色で測ると 3px 低く出る。
  1 列を読めば、面と帯の境が出る (図の [Comp] は面が y49..83、帯が y84..86 で、箱の高さは 38)。
- **実害の記録** (2026-09-20): 5 つの部品を面の色で測っていた。SSMCS の [Comp]・[EQ]・[Mid]・
  [Side Chain] と、Knee のプルダウン。実装した後に、撮影と図を比べ直して気付いた。

## Changing how a row is centred

- **決定**: 行の中央寄せの仕組みを替えたら、字の位置を、インクの行で図と突き合わせ直す。中央に
  そろったかを箱の位置で見るテストは、箱の高さも assert する。
- **実害の記録** (2026-09-20): カードの画面のパス欄を、flex の `align-items: center` から
  `line-height` に替えたら、インクの行が y67..75 から y66..74 へ上がった (p089-1 は 67..75)。36px の
  箱では `line-height: 38px` で元に戻り、撮り直した画面は変更前と 0 画素差になった。替えた理由は、
  flex の項目は幅が箱を超えると、いつも末尾の側が切れるため。末尾を残すには、箱を `direction: rtl` +
  `text-align: left` にして、中の字を `direction: ltr; unicode-bidi: isolate` で囲む (ガイドの
  「Folder name display」が、パスの末尾の側を見せると書いている)。
- **実害の記録** (2026-10-12、[#70](https://github.com/semnil/urx-lcd-sim/pull/70)): ダイアログの
  文面をアイコンの中央へそろえる E2E を、`.dialog-text` の外接矩形の中央で書いたら、修正前の CSS でも
  通った。行の既定の `align-items: stretch` で `p` が 44px に伸び、箱の中央がアイコンの中央と一致
  していた。箱の高さが `18px × 行数` であることも assert して、修正前では落ちる形にした。

## A mark the figure draws is drawn as a picture

- **決定**: 記号は字で描かず、図から起こした絵で描く。同じ記号が、ある画面では字、別の画面では絵に
  なっていたら、先に絵の方を探して、両方をそれにそろえる。
- **実害の記録** (2026-09-22): INPUT の [Φ] とチャンネルビューの Φ を、大文字の Φ の字で描いていた。
  字は縦棒が短い。図の記号は 10x11 で、縦棒が輪の上下に 2px ずつ突き出る。その形の SVG
  (`Icons.phase`) を使っていたのは HOME だけだった。字の候補 6 種 (Φ・φ・ϕ・ɸ・Ф・ф) を太さと
  大きさごとに画素の差で比べても、どの字も絵ほど図に近づかなかった。

## What a rule or a token actually paints

- **決定**: 規則やトークンがどの字を動かすかは、スタイルシートを読んで決めず、数える。値を番兵
  (41px など) に替えて、computed の大きさが変わる要素を、全部の画面で集める。docs に書く値は、
  描かれているものと突き合わせる。`src/style/font-reset.test.ts` が、一度も描かれない宣言を見つける。
  見るのは、各画面を開いた直後、種類ごとにボタンを 1 つ押した状態、サイドのタブで切り替えるページ。
- **理由**: `.lcd button { font: inherit }` は、1 クラスの規則より強い。ボタンや入力欄に 1 クラスで
  書いた大きさ・太さ・行の高さは描かれない (ボタンの規則の書き方は
  [design-tokens.md](../design-tokens.md) の「書体」にある)。
- **実害の記録** (2026-09-21、書体を替えて大きさを測り直したとき。全部の画面の平均の差は 5.711 から
  5.486 になった):
  - ボタンと入力欄に書いた大きさ・太さの 18 の規則が、一度も描かれていなかった。docs は、その値
    (EQ のつまみの名前の太字、[Default] の 12px など) を書いていた。1 つずつ効かせて測り、どの画面も
    悪くならないもの ([Default] の 13px・600、サンプリング周波数のボタンの太字) だけを残して、残りは
    消した。
  - 同じリセットの `color: inherit` が、ボタンに書いた文字色 20 件を消していた。2 件を除いて白で、
    その 2 件は灰と黒だった。未点灯の名前が写る 6 枚の図では、名前は白 (描かれていた色) だったので、
    宣言を消した (88 枚の撮影はどれも変わらなかった)。2026-09-22 に、シートとドロップダウンの中に
    もう 3 件が見つかった。当時のテストはそこを開いていなかった。今は、各画面でボタンを種類ごとに
    1 つずつ押す。
  - 大きさの候補を、`font-size: 0` の規則 (絵で描く印) にも出していた。箱そのものの要素 (値の箱・
    ボタン) に `translate` を足すと枠ごと動くので、位置を合わせるのは字だけの要素に限る。
  - `!important` の付いた規則をスタイルシートの上に重ねて測った値と、同じ値を規則に書いた後の値は
    食い違った (5.560 と 5.479)。`!important` は、より詳細な状態の規則にも勝つため。候補は、規則を
    その場で書き換えて測る。
  - 図と中身の違う字 (LICENSE の本文) は、小さくするほど差が減るだけなので、候補を出さない。
  - docs の字の大きさの表の見本 5 行のうち 3 行 (`1-knob`・`Monitor`・`Post Fader Send for FX`) は、
    そのトークンの字ではなかった。見本を差し替えた。
  - 色の宣言の有無は、CSS を走査して確かめる。ブラウザでリセットの `color` を外して読むと、宣言の
    無い要素には、ブラウザ既定のボタン・入力欄の黒が出る。シーン名の箱と CH SETTING の Name を、
    それで「黒の宣言がある」と誤って報告した。
- **実害の記録** (2026-10-12): MONITOR の [CUE Interrupt] の 2 行が 17px 間隔で、p070-1 は 14px
  だった。`font: inherit` は `line-height` も受け継がせるので、1 クラスの `line-height` は描かれない。
  2 クラスで書いた ([#71](https://github.com/semnil/urx-lcd-sim/pull/71)。同じ PR で、テストが
  `line-height` とサイドのタブのページも読むようにし、見つかった 3 つの宣言を消した)。2 行の名前の
  行の間隔を図と比べるときは、インクの行を、箱ごと・字ごとに読む。ボタン全体で読むと、下へ突き出る
  `/` や複製マークが行に混ざる。
- **実害の記録** (同じ日): SETUP の名前に足した `translate` は何も動かさず、既にあったものを 5px に
  しても動かなかった。名前はインラインの `span` で、`translate` はインラインの要素には描かれない。
  ボタンの中の `span` は、ボタンの `padding-top` か、`position: relative; top` で動かす。採点で選んだ
  ずらしを書き込む前に、書き込んだ後の撮影が動いたかを見る。

  480x289 のほかの図 6 枚は、8 行を引いた位置で描画と一致したので、ずれていたのはこの値だけだった。

## Names on the bank list are white

- **決定** (2026-09-21): 開いたチャンネルバンク一覧の名前は、HOME のバンクボタン (p048-1) と同じ白に
  する。`src/style/columns.test.ts` と docs が固定している。図の無い画面の色は操作者が決め、
  コントラストの監査では覆さない。
- **経緯**: 開いた一覧の図は無い。2 つの案を並べた。COLOR 画面の規則 (白と黒のうちコントラストの

  AA に届かない)。白が選ばれた。
